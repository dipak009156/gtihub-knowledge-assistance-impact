THE CORE THEME: Why GKA is NOT Just Another LLM Chatbot
Generic AI tools (like ChatGPT or Copilot Chat) are stochastic sequence-prediction models. They guess from token probability, hallucinate non-existent functions, and cannot compute multi-hop dependencies. GKA is a deterministic compiler-level intelligence engine that constructs a formal AST mathematical graph of the codebase before invoking AI, providing 100% verifiable citations.

1. Technical Implementation & Core Logic

  • Deterministic Call Resolution: Analyzes AST Call nodes and resolves target symbols. It resolves intra-file calls and traverses from module import symbol statements across the entire project import tree.
  • The Certainty Classification Engine:
    • certain (Solid Blue/Red lines): Direct static calls where the symbol definition is uniquely and deterministically proven.
    • uncertain (Dashed Amber lines): Dynamic dispatch, runtime attributes, polymorphic methods, or external libraries.
  • Multi-Hop Blast Radius Engine: Computes the transitive closure of affected code using breadth-first traversal up to 5 hops deep. Calculates dynamic risk tiers (Low, Medium, High, Critical) based on affected caller count and file blast radius.
  • Presentation-Grade CAD Canvas: Hardware-accelerated Cytoscape canvas featuring a blueprint dot grid, multi-tier semantic colors (Violet for classes, Emerald for functions, Sky Blue for hubs), 1-click Architecture Backbone filter, and 2x PNG/JSON snapshot exports.
# backend/app/impact/engine.py - Multi-hop Blast Radius Calculation def calculate_blast_radius(session: Session, target_id: int, max_depth: int = 3): visited, queue = set([target_id]), deque([(target_id, 0)]) impacted_nodes = [] while queue: curr_id, depth = queue.popleft() if depth >= max_depth: continue callers = session.query(Edge).filter(Edge.callee_id == curr_id).all() for edge in callers: if edge.caller_id not in visited: visited.add(edge.caller_id) queue.append((edge.caller_id, depth + 1)) impacted_nodes.append((edge.caller_id, depth + 1, edge.certainty)) return impacted_nodes

  • ML Defect Propensity Formulation: Computes a mathematical risk score for every file in the repository: $$ ext{Defect Score} = w_1 \cdot ext{Complexity} + w_2 \cdot ext{Churn Velocity} + w_3 \cdot ext{Centrality Rank}$$ Files with high cyclomatic complexity, rapid author churn, and high graph centrality are mathematically predicted as regression hotspots.
  • Agentic PR Reviewer: Evaluates proposed git diffs. Traces modified symbols, detects breaking interface contracts (removed parameters, modified signatures), calculates blast radius, and assigns an automated verdict: APPROVED, REVIEW_REQUIRED, or BLOCKED_HIGH_RISK.
  • Unit Test Synthesizer: Generates targeted, production-ready pytest suites based on actual caller-callee argument contracts and edge case null checks.
# backend/app/ml/defect_predictor.py - Defect Propensity Scoring norm_complexity = min(1.0, complexity / 50.0) norm_churn = min(1.0, commit_count / 30.0) norm_centrality = min(1.0, degree / 20.0) # Weighted statistical risk formulation risk_score = round(0.40 * norm_complexity + 0.35 * norm_churn + 0.25 * norm_centrality, 3) risk_level = "High" if risk_score >= 0.65 else ("Medium" if risk_score >= 0.35 else "Low")
